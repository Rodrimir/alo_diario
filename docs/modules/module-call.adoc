|Description
|Ciclo de vida da ligação: agendador, retentativas, disparo, status e a porta `b.c.c.c.VoiceCallGateway`. Adaptadores em `call.vapi` e `call.mock`.
|Base package
|`br.com.cuida.call`
|Spring components
|_Services_

* `b.c.c.c.CallProcessing` -- API pública para o pipeline pós-ligação (módulo `analysis`) e para a retenção (módulo `recording`). Cada método é uma transação curta e idempotente.
* `b.c.c.c.CallQueries` -- Consultas de ligações para os outros módulos (API pública).

_Configuration properties_

* `b.c.c.c.CallProperties` -- Regras do ciclo de ligações.

_Others_

* `b.c.c.c.VoiceCallGateway` (via `b.c.c.c.mock.MockVoiceCallGateway` -- Gateway de voz simulado (padrão no dev e nos testes). Não liga para ninguém: depois de `app.voice.mock.delay`, entrega ao `b.c.c.w.WebhookInbox` os mesmos eventos que o Vapi mandaria (`status-update` e `end-of-call-report`), no mesmo formato. Assim, o fluxo do webhook em diante é exatamente o de produção.)
* `b.c.c.c.VoiceCallGateway` (via `b.c.c.c.vapi.VapiVoiceCallGateway` -- Liga pelo Vapi (`POST /call`) com um assistente <b>transitório</b>, montado a cada ligação com as perguntas do idoso. Como o Vapi não envia as credenciais da organização para assistentes transitórios, o segredo do webhook vai em `assistant.server.headers`.  
+
Sem retry (um POST que estourou o tempo pode já ter criado a ligação); só circuit breaker, para não insistir quando o Vapi está fora do ar.)
|Bean references
|* `b.c.c.e.ElderlyDirectory` (in Elderly) -- API pública do módulo para os demais: consulta de idosos e checagem de acesso.  
+
Idoso de outro tutor responde 404 (não 403), para não revelar que ele existe.
* `b.c.c.s.CallSchedules` (in Schedule) -- API pública do módulo: agendas ativas para o agendador de ligações.
* `b.c.c.q.Questionnaires` (in Questionnaire) -- API pública do módulo: o snapshot do questionário vigente, gravado em cada ligação.
* `b.c.c.s.security.CurrentUserProvider` (in Shared) -- Lê o usuário autenticado do contexto do Spring Security.
* `b.c.c.w.WebhookEvents` (in Webhook) -- API pública do módulo para quem processa os webhooks: lê o payload e registra o resultado.
* `b.c.c.w.WebhookInbox` (in Webhook) -- Porta de entrada dos webhooks (API pública do módulo): grava o evento e publica `b.c.c.w.WebhookReceived` na mesma transação. Um evento repetido (mesmo provedor e id) é reconhecido e descartado, inclusive quando duas entregas chegam ao mesmo tempo.
|Events listened to
|* `b.c.c.w.WebhookReceived` (async)
